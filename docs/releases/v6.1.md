# v6.1: fully automatic: videos in, cycle counts and times out

Tag `v6.1` (20 Nov 2026). Code: `count_cycles.py`, `src/auto_setup.py`, `src/run_v6.py`.
This release also contains v6 (26 Oct 2026), which was not released on its own.

## Summary

Counts the work cycles of a NACHI industrial robot arm filmed by a fixed camera and times every cycle, with no
labelled training data and now with nothing to set by hand. For each video, an automatic setup finds the robot, a
point on its base and its home frame. SAM (ViT-Base) then outlines the robot, looking at more frames when the robot
moves fast or is near home, and PoseRAC's two-threshold trigger counts each home → away → home trip. One command runs
everything:

```bash
python count_cycles.py my_videos_folder/ --out results/
```

## What changed from v5

**v6 (tracker):**
- **Dynamic frame rate.** SAM looks at 2 frames a second (v5's frames), 6 a second when the robot moves fast, arrives
  at or leaves home, or the tracker is unsure, and every frame while the robot moves fast near home. On speeding up it
  goes back over the frames it skipped, so the start of a movement is not missed.
- **Set-up memory.** A still part of the robot that was in the set-up outline and still looks the same may come back
  into the outline. v5 could never re-add a still part it had lost (nachi_4's base, its 3 misses).

**v6.1:**
- **Automatic setup** (`src/auto_setup.py`): from the first 120 s of the video, finds where the robot works (the
  biggest patch of pixels that keep changing), the home frame, a rough robot shape, a SAM outline of it, the box around
  it and the lowest never-moving part as the base point. Nothing to draw or click.
- **One command** (`count_cycles.py`): takes one video, several, or a folder. Writes, per video, `setup.json`,
  `setup.jpg` (the setup drawn on the home frame), `result.json`, `cycles.csv` and `trace.npz`, plus a summary across
  videos. Downloads and checks the SAM weights on first use, picks the device (CUDA, Apple Silicon or CPU) and loads
  SAM once for all videos. Optional labels to score against, or a setup given by hand.
- **Per-cycle times:** start (leaves home), end (back home), duration, wait at home and period for every cycle.
- **Videos decoded while running** (no frame extraction), and cluster jobs can share one job list.
- The counting rule is unchanged.

## How to run

```bash
git clone https://github.com/arrya-sridhar/Pose-RAC-SAM-cycle-counting-.git
cd Pose-RAC-SAM-cycle-counting-
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt                                 # plus ffmpeg (or the one in imageio-ffmpeg)

python count_cycles.py my_video.mp4 --out results/              # one video
python count_cycles.py a.mp4 b.mp4 c.mp4 --out results/         # several
python count_cycles.py my_videos_folder/ --out results/         # every video in a folder
```

Options: `--labels <folder>` (known cycles, to score), `--setup <file or folder>` (give the setup by hand),
`--device auto|cuda|mps|cpu`, `--skim <seconds>`. Look at `setup.jpg` for each video before trusting its count.
Speed: about 0.3 s per second of video on a cluster GPU (H200), about 3 s per second of video on an Apple laptop GPU.
More in the README (Quick start).

## Known limits

- **The automatic setup is checked on 2 videos of one program only.** It assumes the robot is the biggest moving thing
  in view during the first 2 minutes and is at home (or still) early on. On NACHI its outline can take in the switch
  box on the wall next to the robot. If `setup.jpg` looks wrong, give the setup by hand (`--setup`).
- On the new simulated videos (several arms, people walking through, moving cameras, very short cycles) the automatic
  setup and the tracker mostly fail. That is the next version's work (v6.2).
- nachi_4 counts are fragile: they can change by one with tiny differences in the input, and on the non-uniform
  videos nachi_4 is only 9/20 exact.
- Fixed camera only, one robot per video.
- `count_cycles.py` has been run on a Mac (Apple GPU). The 400-video cluster run used `src/run_v6.py` with job lists,
  which `count_cycles.py` calls unchanged.
