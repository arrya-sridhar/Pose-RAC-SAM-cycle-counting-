# v5: a box that follows the robot, a wall check, recovery and hold

Tag `v5` (13 Oct 2026; results from 25 Sep 2026). Code: `src/run_real.py`.

## Summary

Counts the work cycles of a NACHI industrial robot arm filmed by a fixed camera, with no labelled training data.
Every half second, SAM (ViT-Base) outlines the robot, prompted by a box that follows the robot plus one click on its
base. Each outline is compared with the robot's outline on the first frame (its home pose), and PoseRAC's
two-threshold trigger counts each home → away → home trip as one cycle. It also reports the time of each return home.

## What changed from v4

- **Recovery:** after 1 s with no acceptable outline, it also prompts SAM with the first-frame box and with a box
  around everything that moved since the last good outline.
- **Hold:** if no candidate passes the checks, the last good outline is kept for that frame.

These fixed nachi_7, where the tracker had been stuck with an oversized box. The full rule set is in the README
("How v5 works") and the history of every version in `HISTORY.md` Section 3.

## Results

| Test set | v5 | Earlier pipeline (fixed box + area autocorrelation) |
| --- | --- | --- |
| All 200 dataset videos (3,141 cycles) | **197/200 exact (98.5%)**, 200/200 within one cycle, MAE 0.002 | 167/200 exact (83.5%) |
| 9 edited videos with uneven cycles (33 cycles) | **9/9** | 6/9 |
| 10 development videos | **10/10** | 9/10 (our re-run; 10/10 in its own run) |

- The three misses (nachi_4_seq_014, 016, 018) are each one cycle short: the outline loses the robot's black base
  during the 2nd cycle and never gets it back, and a brief dip at the 6th return then merges two cycles
  (`HISTORY.md` Section 6.1).
- On the edited videos all 33 cycle ends were found exactly once, a median of 0.8 s early.
- Caveats: the 200 dataset videos are built from the same 10 one-cycle recordings repeated back to back, and v5 was
  developed on 10 of them, so the edited videos are the fairest test.

Full numbers: `results/dataset_200/metrics.txt` and `results/dataset_200/per_video.csv`.

## How to run

See the README (Setup, Usage). In short: download the SAM ViT-B weights, then for each video give a box around the
robot and one click on its base, in 1280×720 coordinates, on a frame where the robot is at home:

```bash
python src/count_video.py --video clip.mp4 --box 430 180 950 719 --click 754 598 --out result.json
```

## Known limits

- The box and the base click have to be set by hand for each camera set-up.
- Fixed camera only.
- The robot has to pause at home; robots that never pause or very short cycles fail at 2 frames per second
  (`HISTORY.md` Section 6.2).
- Cycle-end times are rougher than the counts (`HISTORY.md` Section 6.3).
